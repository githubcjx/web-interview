## 第 1 次会话 ｜ 时长约 60 分钟
- **本次内容**：**🏠 小程序模块开荒**，一次讲一个点 + 立即复述（新教学纪律首次执行）。
  1. **双线程架构**：逻辑层（JsCore，无 DOM/window）vs 渲染层（WebView），两层不能直连、必须经原生层转发；设计动机（① 安全与管控——微信对第三方代码的物理隔离手段；② 性能隔离——JS 重计算不冻结渲染）；代价（直接调用 → 跨线程通信，序列化 + 传输有成本）。
  2. **setData 优化**：核心成本模型 **`成本 ≈ 单次数据量 × 调用频次`** → 三个方向 **少传 / 少调 / 不传**。少传（数据路径 `'list[2].done'`、data 只放渲染数据、`pureDataPattern` 纯数据字段、单次上限 1024KB）；少调（节流 ← 串联本周手写题、**"先判断状态是否真变再 setData"** 一行 if 消灭 98% 通信）；不传（**WXS 运行在渲染层**，滚动动画零跨线程）。
  3. **性能定位方法论**：必须真机（模拟器非真双线程，测不出跨线程成本）；用 **`setData` 的渲染完成回调**量端到端耗时（≠ 调用前后打点）；`JSON.stringify(data).length` 量数据量；二分归因——量大走"少传"、频高走"少调"。
  4. **登录鉴权链路（code → session）**：六步全链路；三条安全铁律（AppSecret 只在后端 / **session_key 绝不下发** / **不能拿 openid 当登录态**）；⭐ 深挖"为什么绕一道 code"→ **OAuth 2.0 授权码模式**；openid vs unionid；`wx.checkSession()`；**手机号获取已查证最新方案**（`getPhoneNumber` 回调拿 code → 后端调 `phonenumber.getPhoneNumber` 换取；该 code ≠ wx.login 的 code；基础库 2.21.2 起无需提前 wx.login；旧的 `encryptedData` + `iv` + session_key 解密方案已被取代）。

## 第 2 次会话（同日续接）｜ 时长约 40 分钟
- **本次内容**：
  - **教学纪律调整（他本人提议，已采纳并写入 progress.md）**：① 一次只问 1 题，答完追问、追问完再下一题；② 同一天刚讲的内容不做滚动复习（测短期记忆，无留存价值），只复习上次及更早的内容。
  - **小程序分包加载**（主线，全程一次一题）：
    - 基础：2MB 单包硬限制的真实动机（**微信在强制你保证启动性能**，不是小气）；分包 = 把"启动全量下载"改成"按需下载"；三条规则（tabBar 必须在主包 / 分包可用主包不可用其他分包 / 主包不能引用分包）；拆分判据"**是不是人人一进来就要用**"；图片上 CDN。
    - **分包预下载 `preloadRule`**：触发粒度是**页面级**（进入 A 页面时预下载 B 分包），`network` 默认仅 WiFi（预下载是"赌用户会用"，赌错就是白耗流量）；归类到前端预加载通用套路（prefetch / 路由预取 / 图片预加载）。
    - **独立分包 `independent: true`**：动机（分享落地页用户空降，不该被迫下载用不到的主包）；两个代价——**不能引用主包/其他分包**（要用就得复制，拿代码冗余换启动速度）、**`getApp()` 拿不到实例**（主包未下载、app.js 未执行，需 `getApp({allowDefault:true})`，线上易踩）。
    - **话术训练首次开展**：模拟"包体积超了 2MB 怎么处理"，让他自组织 1-2 分钟面试口语版，逐条打磨。
  - 查证：单包 2MB 上限已确认；**所有分包总上限未能从官方文档确认**（微信调整过，早期 20MB 后上调），已如实告知不给未验证的数字，让他面试前自行核对。
- **表现评价（本段状态很好）**：
  - **Q1（分包引入什么新问题）半对**：答出"首次进入分包会慢"✅，但答不出缓解机制。已升级表述为"**分包没有消除等待，只是把等待从启动时转移到首次进入时**，且更刺痛——用户已表达意图却得不到响应"。
  - **Q1 追问走偏一次**：提示"手机闲着怎么利用"后答"先渲染一部分再慢慢填充"（骨架屏）。已纠正一个有价值的分界：**骨架屏解决"数据还没到"，分包问题是"代码还没到"——连渲染骨架屏的代码都没有，无米之炊**。给"预"字提示后即答出**预加载** ✅。
  - **Q2（分享链接空降进分包页）✅ 完全正确，且自己推出了设计动机**——"要下主包+分包，不合理，应该只下分包资源"。**这是他第二次自主推导出机制的存在**（上次是主动做 WXML/Vue 类比），知识串联的突破在延续。
  - **话术训练 7/10**：结构完整（定位→手段→权衡）✅、**主动讲权衡** ✅（这是长期训练目标，自发做到了）、图片上 CDN ✅。三个缺口：

    - ② **最关键：讲了权衡却没讲缓解**。"进二级页面会慢，这是权衡后的决定"在面试里减分，听起来像接受问题而非解决问题——**而 preloadRule / 独立分包正是刚学的还账手段**。已立通用话术规则：**讲权衡永远要跟一句"我怎么补的"**。
