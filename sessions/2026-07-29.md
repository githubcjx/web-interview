## 第 1 次会话 ｜ 时长约 60 分钟
- **本次内容**：**🏠 小程序模块开荒**，一次讲一个点 + 立即复述（新教学纪律首次执行）。
  1. **双线程架构**：逻辑层（JsCore，无 DOM/window）vs 渲染层（WebView），两层不能直连、必须经原生层转发；设计动机（① 安全与管控——微信对第三方代码的物理隔离手段；② 性能隔离——JS 重计算不冻结渲染）；代价（直接调用 → 跨线程通信，序列化 + 传输有成本）。
  2. **setData 优化**：核心成本模型 **`成本 ≈ 单次数据量 × 调用频次`** → 三个方向 **少传 / 少调 / 不传**。少传（数据路径 `'list[2].done'`、data 只放渲染数据、`pureDataPattern` 纯数据字段、单次上限 1024KB）；少调（节流 ← 串联本周手写题、**"先判断状态是否真变再 setData"** 一行 if 消灭 98% 通信）；不传（**WXS 运行在渲染层**，滚动动画零跨线程）。
  3. **性能定位方法论**：必须真机（模拟器非真双线程，测不出跨线程成本）；用 **`setData` 的渲染完成回调**量端到端耗时（≠ 调用前后打点）；`JSON.stringify(data).length` 量数据量；二分归因——量大走"少传"、频高走"少调"。
  4. **登录鉴权链路（code → session）**：六步全链路；三条安全铁律（AppSecret 只在后端 / **session_key 绝不下发** / **不能拿 openid 当登录态**）；⭐ 深挖"为什么绕一道 code"→ **OAuth 2.0 授权码模式**；openid vs unionid；`wx.checkSession()`；**手机号获取已查证最新方案**（`getPhoneNumber` 回调拿 code → 后端调 `phonenumber.getPhoneNumber` 换取；该 code ≠ wx.login 的 code；基础库 2.21.2 起无需提前 wx.login；旧的 `encryptedData` + `iv` + session_key 解密方案已被取代）。
