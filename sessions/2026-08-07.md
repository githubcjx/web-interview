  ### 二、浏览器缓存（新模块，全程表现好）
  - **两级分工的复述 ✅** 并自己举中 `index.html` 作为"不敢用强缓存"的例子。
  - **hash 文件名的两问 ✅ 全对**（hash 由内容算 / HTML 被强缓存会导致旧 HTML + 旧 JS）。已补精髓：**缓存的 key 是 URL，内容变 → URL 变 → 是全新资源，根本走不到缓存**；设计价值是**把"更新"和"缓存"解耦**。
  - **`Last-Modified` 两个缺陷 ✅ 全对**（秒级精度、内容没变但时间变）。已补第三条：分布式多机 mtime 不一致。
  - **"为什么不全用 ETag" ✅**（计算开销）。已补：Nginx 默认用 mtime+size 生成 ETag，集群同样不一致 → 实践中很多团队干脆只靠 hash + 强缓存。
  - **收尾排障题（发版后 404 白屏）2.5/3**：链条 ✅、根因 ✅；解法只答出"HTML 不设缓存"和"弹窗提示刷新"，**漏了「发版不立刻删旧资源」这一层**，而这层专治跟 HTML 缓存无关的变种——**用户开着页面跨越发版 → 懒加载 chunk 404（`ChunkLoadError`）**。
  - **⚠️ 表述精度问题当场复现**：答"不给 HTML 设置缓存"——**十分钟前刚讲过 `no-cache`（每次协商）vs `no-store`（真不缓存）的区别，实际表述时仍滑过去**。这正是该考点的头号翻车点。
