- **表现评价**：

  ### 一、摸底（先让他按现有理解讲一遍）
  他的原始版本：`查缓存 → DNS → 三次握手 → 传输 → 四次挥手 → 浏览器渲染，结束`。
  **网络半条链是通的、顺序无误**，三个洞：
  1. **HTTPS/TLS 握手缺失**（只讲 TCP 三次握手）——现在没有站点跑 HTTP，不提会被判定"背的旧版本答案"。
  2. **漏了"服务器处理并响应"整站**（CDN / 反向代理 / 重定向都挂在这里）。
  3. **渲染流程 = 0**（原话"浏览器开始进行渲染页面的流程，结束"）——而这正是 🔴 标记的主战场。

  ### 二、已建立的骨架（七站，1 分钟可讲完）
  URL 解析 → **查缓存** → DNS → **TCP + TLS 握手** → 请求/服务器处理/响应 → **浏览器渲染** → 断开（keep-alive，不是传完就挥手）。
  **已教答题策略**：这是**地图题**，面试官看的是**版图有没有洞**，然后挑一站深挖。正确打法是**先给清晰骨架、每站用词精准但点到为止，把深挖权交给面试官**，而不是一上来狂讲 DNS 细节。加分句：**"如果强缓存命中，第 3~6 站全部跳过"**——体现的是阶段间关系而非顺序背诵。

  ### 三、渲染流水线（本次主菜，从 0 到能扛追问）
  | 考点 | 结果 |
  |---|---|
  | `<script>` 为什么阻塞 HTML 解析 | ✅ 一次答对（JS 能增删改 DOM）；已补 `document.write` 与 `defer`/`async` 区别 |
  | **CSS 还没下载完，后面的 JS 能执行吗** | **✅ 答对（第三层，很多 5 年经验卡这）**——"JS 可能读样式，要等 CSSOM" |
  | 主线程四步复述（样式计算/布局/分层/绘制） | ✅ 准确 |
  | 改 `background-color` 哪几步重跑 | ⚠️ **漏了「样式计算跑不掉」**，以为只走绘制 |
  | `transform` vs `left` 为什么快 | ⚠️ 方向对（GPU、流水线短），但**低估**：以为"从光栅化开始"，实际**连光栅化都跳过，只重新合成** |
  | 迁移题：读 `offsetHeight` 为什么慢 | ✅ 核心答对（强制同步布局）；⚠️ 精度差见下 |

  - **⭐ 高光**：CSS 阻塞 JS 那一问是真正的第三层追问，他**没有提示就答对**。由此串成的完整因果链已入话术库：**CSS 不阻塞 HTML 解析，但阻塞 JS 执行；JS 阻塞 HTML 解析 → 所以 CSS 间接阻塞 DOM 构建**。"CSS 放头部、JS 放底部"从口诀变成了推论。
  - **已补的三个精度点**：
    1. **回流 vs 重绘的机制定义**：回流 = 从**布局**开始重跑全套；重绘 = 跳过布局、从**绘制**插入。「回流一定引起重绘」的原因就是"从更靠前的步骤重跑，后面自然全被带上"。**但样式计算两者都跑不掉。**
    2. **绘制(Paint)产出的是"绘制指令列表"，不是像素**——是施工图纸不是成品，真正的像素在**光栅化**（GPU）阶段。这是最多人误解的一步。
    3. **`transform`/`opacity` 只需重新「合成」**：图层位图已存在，只是贴的时候换个变换矩阵/透明度。**杀手推论：合成在合成线程，所以主线程被 JS 卡死时 `transform` 动画照样丝滑、`left` 动画直接冻结**（可现场演示 `while` 死循环）。已配代价：需提升为独立图层，`will-change` 是"临时声明"不能永久挂着，图层爆炸吃显存。
  - **强制同步布局的关键修正**：他说"修改 height 会再次触发回流"——**单独看，写样式不会立刻回流**，浏览器会攒进队列下一帧统一处理（连改 100 次也只回流 1 次）。罪魁是**读写交替**：读 `offsetHeight` 时队列里有未生效的变更，浏览器被迫**同步 flush 一次布局**。**解法是读写分离（先批量读、再批量写），N 次布局 → 1 次。**
    - 已给会触发强制布局的属性清单：`offsetTop/Left/Width/Height`、`scrollTop/Height`、`clientWidth/Height`、`getBoundingClientRect()`、`getComputedStyle()`——**共同点：都要求"此刻准确的几何值"**。
    - **🏠 已串到他的主场**：小程序 `setData` 同样是异步批量，中间插一次 `createSelectorQuery` 读节点位置也会打断批量。**"异步批量 + 读操作强制 flush"是同一个模式。**

- **新增薄弱点**：
  - **判断"哪几步会重跑"时漏掉「样式计算」**（认为改颜色只走绘制）。
  - **`transform` 的省法说小了**（答"从光栅化开始"，正解"只重新合成"）。
  - **以为"写样式立刻触发回流"**——实际是批量的，读写交替才是元凶。
- **修复的薄弱点**：本次未安排复查（见开头说明）。
