- **本次内容**：Vue 模块大推进（`key`/diff → `keep-alive` → 手写 LRU → 组件通信 → `provide/inject` 深入 → Vuex vs Pinia）。
  1. **`key` 与 diff**：`key` = 节点身份证；无 key 时**就地复用（in-place patch）按位置对应**；**用 index 做 key ≈ 没有 key**，两层后果——① 头部插入导致全量 patch（性能）② **状态错乱**（勾选框/输入框状态跟着 DOM 节点走，复用错位就跟错行，这条才是致命的）。diff 策略：**同层比较**（完整树 diff O(n³)，1000 节点即十亿量级不可用 → 压到 O(n)）、类型不同直接销毁重建。代价：跨层移动时节点被销毁重建，**内部状态一并丢失**。
  2. **`keep-alive`**：与 `key` 是同一根轴的两端（key 变化 = 强制销毁重建；keep-alive = 阻止销毁）。抽象组件、`cache` + `keys`、切走时把 DOM 移入内存容器而非卸载；**`onActivated`/`onDeactivated` 取代 `mounted`**（"每次进页面刷新数据"必须写 `onActivated`，经典踩坑）；`max` 用 **LRU** 淘汰，上限存在的理由是**内存**（缓存的实例 + 整棵 DOM 都占内存）。
  3. **手写 LRU**（趁 keep-alive 挂钩点热，非孤立刷题）。
  4. **组件通信**：先给**按"组件关系"分类的框架**（父→子/子→父/双向/父调子方法/跨层/任意关系/临时事件）再展开；**版本点：`defineModel()` 已在 Vue 3.4 转正**（3.3 实验性），是官方推荐写法，仍讲清"v-model 本质是 props+emit 语法糖"；**为什么 Vue 3 移除 EventBus**（隐式通信不可静态追踪 + 忘解绑内存泄漏 → 转向显式通信）；`provide/inject` 的隐式依赖问题。
  5. **`provide/inject` 深入**（他主动要求细讲）：**传容器不传值**、`reactive` 整体赋值会丢、**`inject` 必须在 setup 同步调用**（依赖 currentInstance 上下文，同生命周期钩子）、**`readonly()` + 一并提供修改方法**（修改权留在提供方）、**`Symbol` + `InjectionKey<T>`**（组件库标配，字符串 key 会冲突且 TS 推不出）、默认值的工厂函数参数、`app.provide()`。
  6. **Vuex vs Pinia**：三条设计动机——① **取消 mutation**（它是为"可追溯性"交的税，Vue 3 响应式 + `$subscribe` 后不用交了）② **取消 modules 嵌套**（字符串路径 TS 推不出；Composition API 让"组合"变廉价，不需嵌套组织）③ **TS 是决定性因素**；两种写法（Option Store / Setup Store）。
- **表现评价（本段状态很好）**：
  - **`key` 状态错乱题 ✅ 一次答对**（"写周报会变成勾选状态，因为它的 index 变成了 0"）。

  - **`max` 淘汰策略 ✅ 行为答对**（淘汰最久没访问的），但**没说出名字 LRU**，也没答"为什么要有上限"（内存）。已连到手写题清单第 5 题。
