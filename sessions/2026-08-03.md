## 第 1 次会话 ｜ 时长约 150 分钟
- **本次内容**：按他要求**开场直接进主线，无铺垫**。🏠 小程序模块推进至内容全覆盖（5/5）。
  1. **长列表（一）为什么小程序比 H5 难**：H5 虚拟列表的三个前提（同步测高 / 同步监听滚动 / 同步改 DOM）在小程序里全被双线程打破 → `createSelectorQuery` 异步测量、滚动事件跨线程滞后、`setData` 再跨一次 → **三重延迟叠加，"隔着一层玻璃做手术"**。
  2. **长列表（二）治流量**：触底加载写 `setData({list:[...old,...new]})` 是**全量传输**，第 10 页为追加 20 条要传 200 条，累计 **O(n²)**，且**卡顿随使用时长恶化**（最难被测出来）。改用**数据路径追加** `list[20]`、`list[21]` → 传输量恒定，O(n²)→O(n)。
  3. **长列表（三）治存量**：**「`setData` 优化的是流量，节点数是存量；流量控住了存量还在涨」**。几千条数据 = 上万节点，内存/布局/合成同时恶化，与传输量无关。唯一解法是**虚拟列表**（节点数不随数据量增长）。
  4. **长列表（四）定高 vs 不定高**：定高 = `scrollTop / 项高` 一次除法，**不需要前缀表**；不定高 = **前缀高度表 + 二分查找**（O(n)→O(log n)），小程序还要叠加 **"预估高度先渲染 → `createSelectorQuery` 异步实测 → 回填前缀表"**，代价是一帧位置未校正的抖动 + 需反向补偿 `scrollTop`。生产优先用官方 **`recycle-view`**。
  5. **跨端选型**：先定约束（投几端 / 性能敏感否 / 团队栈）再看方案；三方案对比表；核心判据 **「跨端框架的全部价值来自"跨端"两个字，只投一端时多一层抽象就是纯负担」**；⭐ **中间道路——先原生 + 把 `wx.*` 封装成适配层，"面对不确定的未来不提前下注，而是降低将来改主意的成本"**。
  6. **移动端适配**：单位演进 px→rem（依赖 JS、有闪烁）→vw（纯 CSS）→**rpx**；核心洞察 **「rpx 就是微信内置的 vw，750rpx ≡ 100vw」**；**1px 边框根因 = 物理像素 vs 逻辑像素**，小程序里 `1rpx` 在 DPR=2 设备上正好 1 物理像素、顺手解决一半；**安全区** `env(safe-area-inset-bottom)` + `wx.getWindowInfo()`；iOS/安卓原生组件差异必须真机双端测。
  - **两处版本查证**（遵守版本时效性原则）：① 跨端框架 2026 现状（uni-app 小程序端覆盖最全、Taro 支持 React/Vue 且更适合复杂工程；"只做微信就该认真考虑原生"）；② **`wx.getSystemInfo` / `wx.getSystemInfoSync` 已废弃**，拆为 `getWindowInfo`（含 `safeArea`）/ `getDeviceInfo` / `getAppBaseInfo` / `getSystemSetting`——面试答旧 API 直接暴露版本。
- **表现评价（今天状态很好，主线题 5/6）**：
  - **Q1（全量 setData 的问题）✅ 一次答对**：主动算出"第 10 页等于更新 200 条"。已升级为面试级表述：**O(n²) 累积 + 卡顿随使用时长恶化**。
  - **Q2（增量之后卡什么）✅ 一次答对**：答出"节点数量 + 卡在渲染层"。已补精度：一条列表项含 5~10 个节点，实际上万；并钉出**「流量 vs 存量」**分界。
  - **Q3（不定高怎么定位起始索引）❌ "想不出来"**：已分两步带讲（前缀和 → 单调性 → 二分；预估+实测回填）。
  - **Q4（为什么前缀表能二分、原始数组不行）⚠️ 归因偏差复发**：他答"复杂度更低、遍历少"——**说的是结果，不是原因**。正确答案：**二分查找的唯一前提是有序**；原始高度数组无序，中间值不携带方向信息，无法排除任何一半。已重构认知：**前缀和真正的价值是"把无序数组变成有序数组"从而解锁二分，省去重复累加只是顺带**。⚠️ 该答案五分钟前刚讲过。
  - **Q5（话术：长列表怎么优化）7/10**：技术点全覆盖 ✅（增量 setData / 节点数 / 前缀表 / recycle-view / 不造轮子）。三个问题：① **技术性混淆——把"固定高度"和"前缀高度表"并列说**，实为互斥两条路（定高不需要前缀表）；② 没有先结论；③ **定位手段只答"查看代码"未答量化**（第 3 次）、**权衡完全没讲**（第 2 次，且我本轮专门提醒过）。已给打磨版。
  - **Q6（uni-app 提前上车对不对）⭐ 他明确反驳我，且反驳有价值**：主张"迁移成本高，现在负担一下值得"。**这个判断本身是对的**，但**漏读了题干的"可能"二字**——把不确定当成确定。已讲透：**确定的持续成本 vs 不确定的未来收益**；资深工程师的第一反应是**澄清确定性**而非急着给方案；以及中间道路。
  - **⭐ Q6 重答一轮即达标**：结论→展开→边界结构齐全，且**主动把"可能"改成了"确定需要多端"**——**一轮之内吸收纠正，这是今天最好的一个信号**。
  - **移动端适配 Q（iPad 上为什么夸张）✅ 一次答对**：答出"750rpx 恒等于屏宽，大屏等比放大"。已钉：**rpx 管缩放，管不了"布局该不该变"**。
